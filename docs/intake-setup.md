# intakeリポジトリ（private）のセットアップと運用

質問の受付から公開までのうち、**回答を書く〜「公開」ラベルを付ける**までがこのリポジトリでの作業。
ラベルを付けたあとは自動で公開リポジトリ（`MikiMakino/cwbj`）へ反映される。

全体像は [flow.html](../flow.html) を参照。

---

## 1. 必要なラベル

| ラベル | 用途 | 付ける人 |
| --- | --- | --- |
| `公開` | このQ&Aを公開する | 運営 |
| `要確認` | 自動チェックで公開を見送った | 自動 |
| `PII確認済` | 個人情報チェックの誤検知を承認する | 運営 |
| `cat:ask` | カテゴリ「質問・相談について」 | 運営 |
| `cat:privacy` | カテゴリ「プライバシーについて」 | 運営 |
| `cat:site` | カテゴリ「このサイトについて」 | 運営 |

カテゴリのラベルを付けない場合は `質問・相談について` に入る。カテゴリを増やすときは公開リポジトリの
`config/site.json` を編集する（ラベル名も合わせて作る）。

## 2. Power Automateが作るIssueの形

Formsの回答から、次の形の本文を組み立てる。見出し（`###`）の文字列が読み取りのキーになる。

```markdown
### 質問
（フォームに入力された質問・相談の本文）

### カテゴリ
（フォームの選択肢。ラベルを付ける場合はラベルが優先される）

### 受付日時
（送信日時）
```

Issueのタイトルは、そのまま公開ページの質問文として使われる。長すぎる・個人情報を含む場合は
運営がタイトルを直すか、本文に次のセクションを足す（こちらが最優先で使われる）。

```markdown
### 公開用の質問
（言い換えた質問文を1行で）
```

🚧【未検証】Power Automate側のテンプレート設定は、実際のフロー編集画面で確認しながら合わせる。

## 3. GitHub App（公開リポジトリへ書き込むため）

Personal Access Tokenではなく GitHub App を使う。権限を1リポジトリに限定でき、鍵を入れ替えられるため。

1. GitHub Appを作成する
   - Repository permissions: **Contents = Read and write** のみ
   - インストール先: **`MikiMakino/cwbj` だけ**（intakeリポジトリには入れない）
2. 秘密鍵（.pem）を生成する
3. intakeリポジトリの Settings → Secrets and variables → Actions に登録する
   - `PUBLISHER_APP_ID` … App ID
   - `PUBLISHER_APP_PRIVATE_KEY` … .pemファイルの中身をそのまま貼る

Issueの読み取りには、ワークフローに自動で渡る `GITHUB_TOKEN` を使う（追加設定は不要）。

## 4. ワークフローを置く

このリポジトリの [`docs/intake-workflow.yml`](intake-workflow.yml) を、intakeリポジトリの
`.github/workflows/publish-faq.yml` としてコミットする。`owner` / `repository` が自分のアカウント名に
なっているか確認すること。

## 5. 回答から公開までの手順

1. Formsの送信を受けて、Issueが自動で起票される
2. 回答をコメントとして書く。**1行目を `### 回答` にする**（これが公開される本文になる）

   ```markdown
   ### 回答

   ご質問ありがとうございます。**運営側で確認**したうえで掲載しています。

   - 箇条書きも使えます
   - リンクは [表示名](https://example.com) の形式で
   ```

   使えるのは、段落・箇条書き・太字・`コード`・httpsリンクだけ。書き直したいときは新しく
   `### 回答` コメントを投稿すれば、**最後のものが採用される**。
3. 質問文とカテゴリを整える（タイトルの修正 / `### 公開用の質問` の追記 / `cat:` ラベル）
4. 質問文・回答から個人情報を取り除く
5. `公開` ラベルを付ける → 数分で公開ページに反映される

## 6. 公開が見送られたとき

次のどちらかに当てはまると、そのIssueは公開されず、Issueにコメントと `要確認` ラベルが付く。

- 回答コメントがない、質問文が空、回答者に書き込み権限がない
- 個人情報の自動チェックに引っかかった（メールアドレス・電話番号・郵便番号・SNSのURL・`@`から始まるアカウント名）

直して再度ラベルを操作するか、ワークフローを手動実行すると再判定される。**誤検知**のときは
`PII確認済` ラベルを付けると、そのIssueだけチェックを飛ばして公開する。

氏名・地名・所属など、機械では判定できない情報は自動チェックでは止まらない。**最終的な判断は人が行う。**

## 7. 取り下げ依頼が来たら

`公開` ラベルを外す。次の実行で公開ページから消える（ラベル操作そのものがワークフローの
起動条件なので、通常は数分で反映される）。急ぐ場合は intakeリポジトリの Actions から
`Publish FAQ` を手動実行する。

## 8. 保守

- GitHub Appの秘密鍵は年1回程度で入れ替える（古い鍵を削除 → 新しい鍵を生成 → Secretを更新）
- Actionsの実行時間はprivateリポジトリの無料枠（月2,000分）から引かれる。1回あたり1分未満の想定。
